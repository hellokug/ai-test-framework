给 expect DSL 新增一种断言

预计 15 分钟 · 3 道自测 + 1 个动手练习 · 前置：无 · 所有代码引用真实文件行号

先决策：真的要改代码吗？

「新增一个断言」有三条路，先走 A，A 走不通再考虑 C。 B 是给一次性需求的泄压阀：

路线 A · 零代码

现有谓词组合

结构类需求大概率已被 resp / json 覆盖，直接写用例：

{"resp": {"path": "model",
          "eq": "gpt-4o-mini"}}
路线 B · 逃生门

手写 test_*.py

一次性、无法用谓词表达的复杂逻辑，写成普通 pytest 文件。 这是刻意设计（YAGNI，docs/functional-testing.md 取舍表）。

路线 C · 本课主线

给 DSL 加新键

当新断言通用、要跨用例复用、且现有谓词表达不了时， 才给引擎加键——五步清单见下。

原理：断言键的一生（加载期 → 执行期）

读懂这张时间线，五步清单每一步的「为什么」就自明了：

load_cases()            Case.__init__（加载期，fail fast）        Case.check()（执行期）
────────────           ─────────────────────────────           ──────────────────────
读 jsonl 每行     →     ① 必填字段 / expect 是对象               按 _status 分流：
                        ② 未知键？对照 _EXPECT_KEYS 白名单         错误响应→只跑 http_status+resp
                        ③ 各键形状校验（类型/取值范围）            正常响应→内容→结构→工具
                        挂了抛 ValueError，整批不进执行池          挂了抛 AssertionError
为什么是封闭集合？键名写错（如 contins）在 加载期立即报错（harness.py:677-679），而不是执行期静默跳过。 如果白名单开放，一个拼写错误会让用例「看起来在测、实际什么都没断」—— 这比崩溃危险得多。

五步清单（以 no_repeat 为实物范例）

下面每一步都对照 no_repeat（复读检测）当年是怎么加进来的：

  1. 白名单加键 — harness.py:68

    把键名放进 _EXPECT_KEYS。就这一行，加载期校验自动生效。

    _EXPECT_KEYS = {"contains", "ignore_case", "nonempty", "json", "tool",
                "tool_args_contains", "no_garbled", "no_leak", "no_repeat",
                ...}
  2. 带参数则加形状校验 — harness.py:682-684

    布尔开关键（如 no_repeat）不需要这步；带参数的键（如 chunks_min）要校验类型与取值范围，非法值加载期拒绝：

    cm = expect.get("chunks_min")
if cm is not None and (not isinstance(cm, int) or cm < 1):
    raise ValueError(f"{source}: chunks_min 须为 ≥1 的整数")
  3. 写检测函数（复杂检测才需要）— harness.py:364

    约定：返回 证据串 | None，None 表示通过。 证据串会被拼进失败消息（「检测到 …」），比布尔值多告诉用户「哪里坏了」。 简单断言（如长度比较）跳过这步直接内联：

    def _repeat_evidence(text: str) -> str | None:
    ...
    if n >= 5:
        return f"整行重复 ×{n}: {line[:40]!r}"   # 非None = 失败证据
    return None
  4. 接线 — harness.py:794 / 818 / 847

    按域放进 _check_content（内容质量）、 _check_shape（结构/流式）、_check_tool（工具行为）。 失败消息固定「期望 X，实际 Y（_brief() 截断）」句式：

    if expect.get("no_repeat"):
    ev = _repeat_evidence(content)
    assert ev is None, f"期望无复读，检测到 {ev}（回复: {_brief(content)}）"
  5. 单测正反例 — tests/unit/test_functional_cases.py:28-43

    夹具 _case(expect) + _response(content) 三行一条： 合法值过、非法响应挂、非法参数加载期报 ValueError。

    def test_no_repeat(self):
    _case({"no_repeat": True}).check(_response("正常回复"))       # 过
    with pytest.raises(AssertionError):
        _case({"no_repeat": True}).check(_response("哈哈哈哈...×10"))  # 挂
影响面小到只有 harness + 测试：expect 对象在落库时原样进 result.raw（storage 层不解析键名），前端只展示不校验—— 新增键不需要动 storage / 前端。

自测三题

动手练习：加一个 max_len 断言

需求：限制回复长度上限（比如防跑飞的 {"max_len": 200}）。现有谓词没有「内容长度上限」，值得加键。

  1. 照五步清单实现（带参数，别忘了第 2 步形状校验）。
  2. 在 tests/unit/test_functional_cases.py 补正反例。
  3. 跑验证命令（这是你的即时反馈闭环）： 
    .venv/Scripts/python.exe -m pytest tests/unit/test_functional_cases.py
做完再看：参考实现 
# ① harness.py:68   _EXPECT_KEYS 加 "max_len"

# ② Case.__init__（仿 chunks_min，harness.py:682 旁）
ml = expect.get("max_len")
if ml is not None and (not isinstance(ml, int) or ml < 1):
    raise ValueError(f"{source}: max_len 须为 ≥1 的整数")

# ③④ _check_content 末尾接线（简单断言，跳过检测函数直接内联）
if "max_len" in expect:
    assert len(content) <= expect["max_len"], (
        f"期望回复 ≤ {expect['max_len']} 字，实际 {len(content)}"
        f"（{_brief(content)}）")

# ⑤ tests/unit/test_functional_cases.py
def test_max_len(self):
    _case({"max_len": 5}).check(_response("hello"))         # 过
    with pytest.raises(AssertionError, match="期望回复"):
        _case({"max_len": 5}).check(_response("hello world"))  # 挂
    with pytest.raises(ValueError, match="max_len"):
        _case({"max_len": 0})                                  # 加载期拒绝
