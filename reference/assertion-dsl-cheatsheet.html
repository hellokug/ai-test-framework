expect 断言 DSL 全集

权威源：aite/functional/harness.py（行号以当前版本为准） · 打印友好，建议常备

一句话模型

cases.jsonl 每行一条用例，expect 对象里放断言键； 键是封闭集合（_EXPECT_KEYS 白名单，harness.py:68）， 加载期就校验，写错立即报错；执行期 Case.check() 按域顺序跑， 失败抛 AssertionError，消息固定「期望 X，实际 Y」句式。

错误模式
_check_error_response
harness.py:867		 http_status整数精确值，或关系形式 {"eq|neq|gte|lte|in": v}；此时 resp 断的是 _body {"http_status": {"gte": 400}}

修饰键：ignore_case（作用于内容域与 json/resp 的部分谓词）。 同一 expect 多键可叠加，全部执行。

执行期两条路径

  1. 响应带 _status（参数校验类错误用例）→ 只跑 http_status 和 resp（harness.py:781-783）。
  2. 正常响应 → 内容 → 结构 → 工具，三域顺序固定（harness.py:788-792）。

新增断言键：五步清单

  1. 白名单加键：_EXPECT_KEYS（harness.py:68）加新键名。
  2. 带参数则加形状校验：仿 chunks_min （harness.py:682-684），非法值在 Case.__init__ 抛 ValueError。
  3. 写检测函数（复杂检测才需要）：约定返回 证据串 | None，仿 _repeat_evidence（harness.py:364）； 简单断言直接内联即可。
  4. 接线：按域放 _check_content / _check_shape / _check_tool；失败消息用「期望 X，实际 Y（_brief() 截断）」句式。
  5. 单测正反例：tests/unit/test_functional_cases.py， 夹具 _case() / _response()（L28-43）；加载期非法用 pytest.raises(ValueError)。
