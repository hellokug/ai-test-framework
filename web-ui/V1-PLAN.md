## 2. 精度模块（最成熟，V1 主战场）

定位（2026-09-24 用户定稿）：精度测试本质 = **选数据集 + 选条数/随机种子 +

YAML 编辑；「评测套件」管理页移出 V1 前端（配置沉淀在后台，V2 再评估是否
需要高级配置页）。
**脚本来源双态（2026-10-12）**：创建抽屉顶部增「脚本来源」切换——
**从脚本发起**（默认；选脚本 + 只读内容快照 + 本次运行参数，spec 整体复用，见 §6A）/
**自定义新配置**（下述六卡表单原样保留，底部「保存为脚本」沉淀入脚本库）。

### 2.1 评测运行 [P0]

回答的问题：跑过哪些评测？结果如何？——入口页。
**不展示成本**（2026-09-24 用户定稿）：token 用量可靠，但换算成钱需要各模型
价格表——本地/私有部署模型无公允单价、API 价格常变，价格表外置仍在后端
backlog；展示算不出来的数字会误导。后端继续记录 usage（token 数是准的），
待可靠计价落地再评估恢复（可先以 token 用量列替代）。

- 统计卡 ×4：累计运行、用例通过率、评测数据集、受测模型
- 筛选行：状态 chips + 套件下拉 + 模型关键字；表格与分页（列不含成本）
  （`GET /runs?domain=accuracy`、`GET /stats?domain=accuracy`）
- **「＋ 创建评测任务」→ 结构化表单（四段按钮组，无 YAML）**：
  1. **评测数据集**（可搜索、可多选列表）：四组筛选——**归属（开源 / 个人 / 客户）**、
     **存储位置（在线 / 离线）**、**能力评估维度（知识问答 / 数学推理 / 代码 / RAG /
     Agent / 鲁棒性 / 长上下文，可多选 OR）**、**数据集类型（LLM / Agent / RAG）**
     （2026-09-24 用户定稿）——
     开源 = 内置/公开基准，个人 = 自建导入，客户 = 客户业务数据；
     在线 = hf 仓库/对象存储引用按需拉取，离线 = 已落地本地（包内抽样版 /
     add-hf 全量 / gen-domain 产物）。数据来自公共·数据集管理（accuracy 型）+ 内置基准目录
  2. **抽样条数与随机种子**：条数预设（全量/100/300/500/自定义）+ seed 输入
     （同 seed 抽样可复现、跨 run 可比）
  3. **目标模型**（radio 卡片）：来自公共·模型管理注册的 gateway 别名（含端点提示）
  4. **并发压力**（radio 卡片）：1/4/8/16 预设 + 场景说明
  高级折叠（可选）：运行名称（缺省自动生成）、阈值判定（auto/不判定/自定义）
- **创建 ≠ 执行（2026-09-24 用户定稿）**：提交 = `POST /accuracy/tasks`（spec 为
  结构化表单形态，§10.1 注）→ 后端组装并**固化配置**（相当于后台写好 YAML），
  生成 task_id（pending），**此时不执行**；实际执行绑定 task_id。执行方式三选：
  **立即执行**（创建后自动 run）/ **定时执行**（scheduled_at，后台调度器到点
  触发 run，触发前可编辑/取消）/ **仅创建**（任务列表手动 run）。同一份配置
  再次执行 = 生成新 task_id（TaskKit retry 链，原配置不变），任务历史按配置
  可追溯多次执行。

### 2.2 运行详情 [P0]（2026-09-24 重构：实时运行视图）

回答的问题：现在跑到哪了？还要多久？哪些挂了为什么挂？日志在哪？

- **实时进度卡**（运行中首要）：进度条 + **总数据条数 / 已运行 / 剩余条数 /
  失败错误数 / 预计剩余时间**（按当前速率估算）+ 当前阶段（引擎 progress 事件，
  含阶段文本与 done/total）；数据源 = SSE（`GET /runs/{id}/stream`，progress 事件
  + total 回写）+ 5s 兜底轮询 run 行，终态自动刷新全页
- **指标汇总**：运行中标注「阶段性」（已完成例数的即时聚合，非最终判定）；
  完成后出最终判定与报告
- **全部失败用例输入输出**：独立卡（断言 → 输入 → 输出），附 failures.jsonl 下载
- **用例抽样结果复核**：按 seed 随机抽样 N 例展示 输入/输出/自动判定 + 人工复核
  标记（待复核/通过/问题），可重新抽样、送人工评测——防“分数对但行为怪”
- **运行日志**：页面只留实时尾部（SSE 追加 + 光标）；完整日志、输入输出明细
  （jsonl）、产物包落盘 work_dir（远端/本机存储），给下载链接——大文件不进页面
- **用例结果完整列表**：可展开行（输出全文 + usage + timings）+ 全部/仅失败过滤
- 基线对比（Δ 列、劣化标红）：已随版本质量对比提前（§2.3）

### 2.3 版本质量对比（趋势页重构，2026-09-24 定稿）

回答的问题：**同数据集、跨版本，分数有没有变差**——这是版本质量的核心判据；
**同模型不同版本精度不允许劣化**（低于基线 = 劣化，阻断项）。

- 图表：**横轴 = 版本号，纵轴 = 分数**；曲线由固定模型 × 固定数据集生成；
  **基线画虚线**（baseline_ref，缺省回退最近 passed run），数据点按
  ≥ 基线标绿 / < 基线标红 染色，劣化点就地标注 ▼ pp 差值
- 筛选：数据集（指标取该集推荐指标）+ 模型多选 + 对比模式：
  **横向**（同模型跨版本，聚焦劣化检测，模型单选）/
  **纵向**（跨模型同数据集，模型多选，各模型基线独立虚线）
- **版本质量判定表**：模型 × 版本 × 分数 × 基线 × Δ(pp) × 达标/劣化 徽章
- **劣化检测面板**：列出全部劣化项（模型/版本/差值/建议阻断发布并回溯变更）
- 移除：雷达图与时间维通过率曲线（非精度分析核心）
- 数据源：趋势查询按 (model, dataset, metric, version) 聚合；基线读取依赖
  D1 基线契约（**从 V2 提前**，见 §8.6）

## 3. 功能模块

左侧菜单：**任务列表 / 任务详情 / 质量大屏 / 版本结果库 / 脚本库 / 评估场景**

### 3.0 定位：从最终目标回推（2026-10-12 用户定稿）

> 需求原话：「我们需要回答**不同版本、不同模型在不同功能维度内的整体表现，对比
> 其他版本是否有优化/劣化、百分比是多少**，最终给测试负责人一个**多维的基于评估
> 场景的质量展示**。」

倒推的功能链路（本模块六个标签页即按此排布）：

```
最终目标  质量大屏（版本 × 模型 × 评估维度，优化/劣化 Δpp，汇报视图）
          ↑ 只读聚合
结果沉淀  版本结果库（任务终态按「被测版本 × 模型」自动归档，分析唯一数据源）
          ↑ 执行产生
任务执行  任务列表/详情（选多个评估场景或场景内子用例 → 执行 → 归档）
          ↑ 归属
资产沉淀  脚本库（脚本 = 用例：测试意图 + 类型标签，可挂外部平台用例编号；1..N 行数据）
          ↑ 归属（先场景后用例）
维度资产  评估场景（API 兼容性 / 参数校验 / FC …）→ 场景内从 0 创建脚本（低代码）
```

术语链（2026-10-12 二轮讨论定稿，修订首轮「脚本 ⊃ 场景 ⊃ 子用例」层级）：
**评估场景 = 功能大类（维度）→ 场景内「脚本 = 用例」（一个测试意图，类型标签
基础/边界/异常）→ 一脚本挂 1..N 行数据（content 内容 + params 参数 + 断言；
行 = 变体，行级执行与判定，脚本结果 = 行级聚合）**。物理形态：**1 脚本 = 1 个
jsonl 文件**（场景目录下）——jsonl 是行级格式不是身份单位。外部平台编写「用例」↔
平台脚本可挂其编号。创建硬约束：**先场景后用例**（场景 = 归档与大屏聚合的维度键）。
脚本两形态：低代码数据行（大部分）/ 复杂脚本 test_*.py（少量；前端内嵌脚本编辑
窗口列入 V2）。评估方法 = 引擎已有断言键族（harness.Case：messages / params /
expect，断言白名单校验）的结构化编辑，前端零评估逻辑——「不造指标」红线不受影响。
**功能域「脚本」语义与精度/性能分叉（各自成立）**：功能 = 用例原子（本节）；
精度/性能 = 任务配置模板（§6A 原口径）。功能域任务创建 = 直接选场景/子用例
（**无「从脚本发起」**）；ft-full 类组合模板随之取消（场景快捷圈选预设保留，
仅作场景选择助手）。

    输入 → 输出）；详情 crumb 带「已归档版本结果库」标记

### 3.3 评估场景与脚本（用例原子，低代码从 0 创建）[P0]

回答的问题：测什么维度？每个场景内有哪些用例（脚本）、怎么从 0 维护？

- **场景卡片网格**：场景 id / 说明 / 用例数 / 维度标签 / **能力覆盖**（基础 x ·
  边界 y · 异常 z——类型是标签不是层级，场景内靠标签覆盖完整能力）/ 形态
  （低代码数据行 | 复杂脚本 test_*.py）/ 操作（**管理脚本**、＋脚本、过滤跑）
- **新建评估场景**抽屉：显示名（场景卡标题 / 场景树 / 大屏维度行名）+ 场景 id
  （目录名，卡副行 / jsonl 路径 / tools.cases 前缀，创建后不可改）+ 维度标签
  （选自**共享标签库** §10.5 dim-tags：新增一次全平台复用，支持行内扩充）+ 说明
  ——创建即注册（目录即注册表，`GET /functional/scenarios` 自动可见，既有惯例不变）
- **从 0 创建脚本**抽屉（主入口，先场景后用例硬约束）：
  ① 归属：评估场景（必选）+ 脚本 id（= jsonl 文件名）+ 脚本名称（测试意图）+
  类型标签（基础/边界/异常/兼容）+ 外部平台用例编号（可选）；
  ② 数据行 1..N：每行 = **content（messages）+ params（透传请求体，可选）+
  断言**（引擎白名单键族多选：http_status / JSON 字段 / 包含关键词 / 非空 / 正则 /
  no_leak / finish_reason / sse_done…）——**三要素固定即脚本完成**；
  保存过 harness.Case 真实校验，物化为 `scenarios/<场景>/<脚本id>.jsonl`
  （**1 脚本 = 1 文件，N 行 = 变体**，行级执行判定、脚本结果 = 行级聚合）；
  同意图多变体可用 vars 占位符生成器（引擎已有能力）
- **从数据集导入**抽屉（并列来源）：目标场景 + 类型 + 平台数据集或粘贴 jsonl →
  整体导入为 1 个脚本（同一校验，不拆散）——「导入本质 = 非前端方式构造 jsonl
  直接生成脚本」
- **管理脚本**抽屉（场景内）：脚本列表（类型 / 行数 / 来源 / 编辑·删除）+
  内容示例（行级 kv：messages / params / expect）
- **功能脚本库页** = 跨场景用例资产视图：脚本（名 + id + 外部用例号）/ 所属场景 /
  类型 / 行数 / 数据行摘要 / 来源（手工 | 导入·集名）/ 定向执行（tools.cases
  精确定向）/ 编辑·删除；类型与来源双维筛选
- 契约：场景 CRUD 与脚本导入见 §10.5；用例（脚本）CRUD 见 §10.4 functional 形态
  （含既有 GET /functional/scenarios 缺口）

## 6A. 脚本管理 · 四域横向能力（2026-10-12 新增）

> 需求原话：「可靠性，功能，性能和精度理论上都要有一些脚本沉淀，比如每个版本
> 固定要测哪些基线数据集，需要增加脚本管理的能力，一个脚本对应一个用例，可支持
> 复用已有脚本和自定义新脚本。」

### 6A.1 概念定稿

- **脚本（script）= 固化的域任务 spec + 名字**：测什么、怎么判在脚本内固化
  （精度 = 数据集/抽样/seed/Judge/阈值/并发/超时/扩展参数；功能 = 场景范围/超时；
  性能 = 引擎/模式/负载/压力参数/chaos 声明；可靠性 = chaos 编排五要素）。
  spec 形态与各域任务创建体**完全同构**（accuracy spec = suite raw，
  见 TOOL-SUITE-PARAMS.md）——脚本即「存了名字的任务配置」。
  **域间语义分叉（2026-10-12 二轮修订，各自成立）**：功能域脚本 = **用例原子**
  （评估场景 ⊃ 脚本 ⊃ 1..N 数据行，见 §3.3）；精度 / 性能脚本 = 任务配置模板
  （本条原口径）。REST 同形（`{D}/scripts`），spec 形态随域。
- **一个脚本 = 一个（版本基线）用例**：新版本发布 = 逐个脚本「发起任务」；同脚本
  跨版本跑出的结果才可进「版本质量对比」（§2.3）与性能跨版本对比——基线口径
  的一致性由脚本保证。术语注意：此「用例」是版本回归语义，与已移出的外部
  「用例平台」（2026-10-09 定位收敛）无关，不恢复用例库页。
- **运行参数不沉淀**：目标模型 / 被测版本（精度，必填）/ 任务名称 / 执行方式属于
  「本次跑谁、跑哪个版本」，发起时指定。脚本编辑即生效；历史任务持创建时配置
  快照，不受编辑影响（可追溯不靠脚本版本化）。
- **两条来源**：① **研发预置** = `examples/{domain}/*.yaml` 随框架版本发布
  （目录即注册表，只读可复制——与 functional scenarios、chaos scenarios 同一惯例，
  17+ 个精度基准套件现成入库）；② **前台沉淀** = 创建任务时「保存为脚本」。
- **复用与自定义并存**：任务创建抽屉顶部「脚本来源」双态（chips 切换，
  v1.js `bindSrcToggles`）——**从脚本发起（默认）**= 选脚本（预置/自定义分组下拉）+
  只读内容快照 + 本次运行参数；**自定义** = 原结构化表单（精度六卡 / 功能场景三层
  选择 / 性能四段编排）+ 底部「保存为脚本」。可靠性域 2026-10-11 已按此模式落地
  （故障观测「保存为场景」+ 场景库发起），本节即其四域推广。
- **性能域既有「保存为套件」按钮更名「保存为脚本」**（同一交互，术语对齐）。

### 6A.2 域内落点（静态稿 2026-10-12 已落）

| 域 | 脚本库页 | 预置脚本（= 现有资产） | spec 固化物 | 运行时覆盖项 |
|---|---|---|---|---|
| 精度 | 侧栏「脚本库」 | 无预置（2026-11-08 预置脚本全删，用户自建沉淀） | 数据集/抽样/seed/Judge/阈值/并发/超时/扩展参数（固化 spec，清单带数据集+条数） | 任务名、目标模型、被测版本*、执行方式 |
| 功能 | 侧栏「脚本库」 | 无预置组合模板（2026-10-12 二轮：脚本下沉为用例原子，ft-full 类组合取消；场景快捷圈选预设保留为选择助手） | 场景 / 类型标签（基础/边界/异常）/ 1..N 数据行（content+params+断言）——1 脚本 = 1 jsonl | 任务名、目标模型、被测版本（任务创建直接选场景，无脚本发起） |
| 性能 | 侧栏「脚本库」 | baseline / ramp / probe / soak 四类压测模板 | 引擎/模式/负载/压力参数/chaos 声明 | 任务名、目标模型 |
| 可靠性 | 既有「故障场景库」（不另建页） | chaos/scenarios/ 目录 + manifest（缺口条目既有） | 对象/武器/观测/背景流量/预期 RTO | fault_duration、背景并发（既有「本次覆盖项」段） |

脚本库页统一结构：说明条（两条来源 + 快照/可追溯语义）+ 列表（脚本名+id+描述 /
内容摘要 / 来源 tag（预置 | 自定义）/ 最近执行 / 更新 / 操作 = 发起任务（开创建
抽屉并定位到该脚本）、编辑+删除（仅自定义）、复制）。任务列表行副行带
「脚本『××』」来源标记（spec 持 script_id 回显）。

### 6A.3 边界与不做

- 脚本不引入版本化 / 审批流（V2 备忘）：编辑即生效 + 任务持快照已满足可追溯。
- 预置脚本前台只读：修改 = 复制出自定义副本（防框架升级被本地改动顶掉）。
- 脚本 ≠ 数据集、≠ 场景：后两者是内容资产（各自目录页演进），脚本只固化
  「选了什么、怎么跑」；功能域场景增删用例不回改已固化脚本。

## 10. 新增 API 契约（按最终规划补齐，2026-09-24 实现）

前端**只依赖本节契约**；四域任务契约与 `docs/domain-backends.md §2` 同形，
数据集契约与其 §12.3 同形。

### 10.1 四域任务 REST（`{D}` ∈ functional / accuracy / perf / reliability）

| 方法与路径 | 语义 | 状态码 |
|---|---|---|
| `POST /api/v1/{D}/tasks` | 创建任务（`{name?, spec}`，spec=域自定义） | 200 |
| `GET /api/v1/{D}/tasks` | 列表（`status` / `retry_of` / `limit`） | 200 |
| `GET /api/v1/{D}/tasks/{id}` | 详情 | 200 / 404 |
| `PATCH /api/v1/{D}/tasks/{id}` | 改 name/spec（仅 pending） | 200 / 404 / 409 |
| `DELETE /api/v1/{D}/tasks/{id}` | 删除（仅终态） | 200 / 404 / 409 |
| `POST /api/v1/{D}/tasks/{id}/run` | 运行（异步，返回任务快照） | 202 / 404 / 409 |
| `POST /api/v1/{D}/tasks/{id}/stop` | 停止（running→stopping→cancelled；幂等） | 200 / 404 / 409 |
| `POST /api/v1/{D}/tasks/{id}/retry` | 重试=新任务（`retry_of` 链） | 201 / 404 / 409 |
| `GET /api/v1/{D}/tasks/{id}/result` | 结果（仅终态；`{task_id,status,result,error}`） | 200 / 404 / 409 |
| `GET /api/v1/{D}/tasks/{id}/stream` | SSE 进度/终态（频道 `{D}:tasks:{id}`） | 200 |

状态机：`pending → running → succeeded/failed`，`running → stopping → cancelled`，
残留由启动扫描收敛为 `stale`。spec 形态 = 各域任务创建体（perf 域 = 压测表单
组装出的 suite raw，reliability = `/chaos/observe` body 同构）。

### 10.2 数据集统一目录 REST

| 方法与路径 | 语义 | 状态码 |
|---|---|---|
| `GET /api/v1/datasets?type=` | 目录列表（type ∈ functional/accuracy/perf） | 200 / 422 |
| `GET /api/v1/datasets/{ref}` | 详情（ref：id 或 `type:name` 或唯一 name） | 200 / 404 |
| `DELETE /api/v1/datasets/{ref}` | 删除登记（文件保留，同 CLI rm） | 200 / 404 |
| `POST /api/v1/datasets/functional/import` | 功能型摄取（`{name,jsonl,notes?,force?}`，过 harness.Case 真实校验） | 201 / 422 |

perf 型登记自动发生于 `POST /perf/datasets`（既有）；精度型经 `aite dataset add-hf` 登记后即可列出。

### 10.3 run / stats 按域过滤

- `GET /api/v1/runs?domain=`：domain ∈ functional/accuracy/perf/reliability；
  过滤规则（单一来源 `service/web_service.run_domain`）：`config.engine` ∈
  {evalscope-perf, locust} → perf；pytest → functional；其余带 engine（evalscope
  等）→ accuracy；无 engine 且带 chaos 声明 → reliability；无 engine → accuracy
  （自研评测 run）。带 domain 时按新→旧扫描上限 `config.MAX_DOMAIN_SCAN` 条后
  内存过滤再分页，`count` 为过滤后总数。
- `GET /api/v1/stats?domain=`：同规则过滤后聚合（前端各模块统计卡数据源）。

### 10.4 四域脚本 REST（提案 · 2026-10-12，契约级待评审后实装）

> `{D}` ∈ functional / accuracy / perf；reliability 域脚本 = chaos scenarios
> （GET/POST /chaos/scenarios 既有缺口条目，不另设 /reliability/scripts）。
> 存储建议：新表 `scripts`（Schema 只增不改；自定义脚本落库——业务状态入 DB，
> 原则 8）；预置脚本 = `examples/{domain}/*.yaml` 目录扫描只读注册，列表合并
> 返回（`source` 区分 builtin/custom），路径即 id 语义。

| 方法与路径 | 语义 | 状态码 |
|---|---|---|
| `GET /api/v1/{D}/scripts?source=` | 列表（预置 + 自定义合并；source ∈ builtin/custom 可选过滤） | 200 |
| `POST /api/v1/{D}/scripts` | 保存脚本 `{name, description?, spec}`（spec = 域任务创建体同构；同名冲突显式报错） | 201 / 422 |
| `GET /api/v1/{D}/scripts/{id}` | 详情（含 spec 全文 = 内容快照数据源） | 200 / 404 |
| `PATCH /api/v1/{D}/scripts/{id}` | 改 name / description / spec（仅自定义；预置 409） | 200 / 404 / 409 |
| `DELETE /api/v1/{D}/scripts/{id}` | 删除（仅自定义） | 200 / 404 / 409 |
| `POST /api/v1/{D}/tasks`（扩展） | body 增 `script_id` + `overrides`（与 `spec` 二选一）：后端加载脚本 spec、深合并 overrides（仅运行参数白名单：name / model / version / execute 等域相关键）后走既有创建管道 | 200 / 404 / 422 |

- additive 说明：`POST /{D}/tasks` 既有 `spec` 形态不变，`script_id` / `overrides`
  为新增可选键（Schema 只增不改）；任务创建后 spec 固化含 script_id 回显。
- **functional 域 spec 形态（2026-10-12 二轮修订）**：spec = 用例原子
  `{scenario_id, case_type, external_ref?, rows[]}`，rows[] 行 =
  `{desc, messages, params?, expect}`（harness.Case 同构）；保存时物化
  `scenarios/<场景>/<脚本id>.jsonl`（1 脚本 = 1 文件，N 行 = 变体）。预置脚本扫描
  仅适用 accuracy / perf（功能域无预置组合模板）；功能域任务创建不走 script 复用。
- 前端触点：创建抽屉「从脚本发起」= script_id + overrides；「保存为脚本」=
  POST scripts；脚本库页 = GET 列表 + CRUD；任务行脚本标记 = 任务详情 spec 的
  script_id 回显。

### 10.6 全局版本管理 REST（2026-10-24 实装；2026-11-11 措辞定稿「创建版本」；同日版本与模型解耦）

> 「公共 · 版本管理」：被测版本号的全局登记表（`model_version` 表，version
> 唯一；model 为遗留列恒空串），跨域共享、与模型无关——精度/功能任务发起时
> 「被测版本」从这里选择，与目标模型自由组合（同一脚本逐版本执行的结果才可
> 做版本间对比）。与 version_result（域 × 版本 × 模型的结果归档，§10.5）是
> 两层：创建先行，归档随后。

| 方法与路径 | 语义 | 状态码 |
|---|---|---|
| `GET /api/v1/versions` | 版本清单（created_at 倒序） | 200 |
| `POST /api/v1/versions` | 创建版本 `{version, description?}`；version 重复 409（旧客户端传 model 兼容忽略） | 201 / 409 / 422 |
| `DELETE /api/v1/versions/{id}` | 删除版本（历史任务/归档持版本字符串不受影响） | 200 / 404 |

前端触点（2026-11-11 统一）：common2 模型管理组独立三页 = 模型/版本/密钥（左侧
独立导航，v1.js GROUP 映射），「版本管理」页 = 清单 + 创建/删除（api32.js）；
精度创建抽屉被测版本 input+datalist = GET /versions（api-acc3.js，「＋ 新版本」
就地创建）；功能新建运行抽屉被测版本 = 全局版本下拉 +「＋ 新版本」就地创建
（api32.js）。三处创建入口均只填版本号（+ 说明可选），不选模型。
