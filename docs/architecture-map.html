这张图怎么用

平台定位一句话：aite 是评测平台不是评测引擎——不造任何评估指标； 评测能力来自开源引擎（evalscope / pytest / locust / ragas），aite 做三件事： 统一入口（suite 的 engine: 路由）、统一结果格式、数据集与任务治理。 所以：想接新评测能力 → 加适配器；想改口径 → 查术语表；想知道能不能改 → 看升级阶梯。
地图分两类内容：实时事实（行数/依赖/接口清单——脚本每次从代码重新提取，永不撒谎） 和内置知识（意图/写法/裁决——逐条与代码校验，代码漂移即拒绝生成）。搜索请用浏览器 Ctrl+F。

适配器与引擎（平台核心资产）

suite YAML 里的 engine: 字段 = 路由开关。五种引擎共用同一契约：build_config → run → collect（+list_tasks），注册表分发，互不认识彼此；结果统一落 run_metric_summary，所以四个域能在趋势页并列对比。

engine 路由名适配器文件怎么执行对接的开源引擎阈值方向关键行为
evalscopeaite/tools/evalscope_adapter.py进程内 run_task()（extra_args.python_exe 可切子进程+文件契约）evalscope 精度基准（可切 OpenCompass/VLMEvalKit/RAGEval 后端）越高越好断点续推 resume auto/force/off + tool_identity_hash 身份指纹；judge 判官经 common.yaml 预制
evalscope-perfaite/tools/perf_adapter.py子进程 evalscope CLI（包无 __main__，shutil.which 定位）evalscope perf——LLM 压测（TTFT/吞吐/延迟分档）越低越好四模式 baseline/ramp/probe/soak；时长双键 duration（整场）/level_duration（每档）互斥
locustaite/tools/locust_adapter.py子进程 locust --headless 逐档执行locust 通用 HTTP 压测越低越好locustfile 由适配器生成（SSE TTFT 自定义事件）；到达模型 poisson/spike/custom；不支持 probe
pytestaite/tools/pytest_adapter.py子进程 pytest -p aite.functional.harness 逐场景 + junit-xml 收集pytest（功能测试：9 场景 64 例 + 用户自建目录）越高越好tools.cases 按 nodeid 精确定向；模型访问经 harness 插件 fixture
evalscope-ragevalaite/tools/rageval_adapter.py进程内 run_task()（RAGEval 后端）ragas（经 evalscope RAGEval 官方后端）——RAG 五指标越高越好平台零指标算法：只做字段映射 / critic_llm+embeddings 注入 / 分数归一；A/B 编排按 records 有无 response 自动分派

位置做什么

list_tasks()枚举引擎侧基准/场景清单（REST /tools/benchmarks 与前端选择器的数据源）
aite/tools/__init__.py顶部加一行 import（noqa: F401 # (registers)）——import 即注册
注册表自动生效list_tools() / GET /api/v1/tools/engines / engine 路由自动认识新引擎；不需要改任何 if-else

术语表（平台唯一口径）

术语含义与落点
Suite / 套件一次评测的完整声明（YAML 文件或 spec 字典）：被测 target + 数据集 + 指标阈值 + 报告格式。loader.py 的 pydantic 模型是它的权威定义
enginesuite 里的路由开关：写了 engine: 就路由到 aite/tools 适配器，不写就走自研引擎
Runsuite 的一次执行实例（test_run 表）。工具域与自研域落同一张表，所以趋势页能并列对比
Case / 用例最小评测单元（输入+预期）。可靠性域会展开 repeat-N / perturb-* 变体再聚合回原 case
Domain / 域accuracy / functional / perf / reliability 四个评测域，各有独立的任务 API、CLI 子命令和任务表
Task / 任务四域后台任务（bg_task + 各域任务表），统一状态机 create→running→succeeded/failed/stale（DomainTaskKit）
Target / 被测系统你要评的东西（OpenAI 兼容端点为主），由 connectors 适配；common.yaml 里可存预制（profile）
ToolAdapter开源引擎适配器契约：build_config → run → collect（+list_tasks），注册表分发
Registry / 注册表名称→组件的字典。全项目三套同构：core/registry.py（连接器/数据集/指标/判官/渲染器）、tools/base.py（适配器）、chaos/injectors/base.py（注入器）
断点续推evalscope 工具域能力：run_state.json 记录完成态凭证 + 身份指纹（tool_identity_hash），没跑完续推、跑完了才全新
SSE 事件流实时进度：频道 runs:{task_id} 与 {D}:tasks:{id}，EventBus 进程内发布，Web 以 /stream 端点透出
上下文收敛Web 启动时把上次进程崩溃残留的 running 任务统一标 error/stale（AppState.startup），状态机闭合

必要性审计（奥卡姆：如无必要，勿增实体）

奥卡姆剃刀的机器化：扫描全部模块的 import 图，找出没有任何其他模块引用的「孤儿」，按调用约定分类裁决；出现真正的死代码 → 生成直接失败（防止死代码静默堆积）。判为正常的类别：包 __init__（由 Python 导入机制加载）与显式入口（CLI/Web/插件名加载/子进程脚本）。
